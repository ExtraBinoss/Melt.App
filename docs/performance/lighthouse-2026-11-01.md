# Landing and dashboard Lighthouse — 2026-11-01

Measured cold navigation in Chrome for Testing **156.0.8078.4**, Lighthouse **13.6.0**,
against isolated production builds. Each audit launched a fresh browser and private
Puppeteer context with empty cache/storage, no extensions and the page foregrounded.
No existing user project/session was used. Standard desktop and simulated mobile
Lighthouse presets were used; mobile models a 4× CPU slowdown and slow mobile network.
Linux processes ran serially at nice 19, with a 200% CPU scope, 3.2 GB memory maximum
and no swap. GPU identification: Intel Arc (MTL), Mesa 26.2.5 / ANGLE Vulkan.

## Changes and evidence

- Remove unprompted landing-to-Studio and dashboard-to-editor idle imports. Real
  pointer/keyboard navigation intent still warms code; opening a project still
  prepares the editor. Desktop dashboard transfers fall by approximately 1.1 MiB.
- Expose pure canvas-format metadata through `@musart/core/presets`, preserving the
  existing root `PRESETS` API. Importing gallery metadata no longer imports document
  factories, editing commands, spatial indexing and SVG path processing on landing.
- Second Skin used to download a 4,369,382-byte original and instantiate the native
  GPU preview automatically on touch. Its immutable gallery card now plays a
  352,205-byte local clip generated by exact native-engine frames, with content and
  source-revision guards. Hover, visibility autoplay, pause and cleanup are retained.
  Other templates retain their native fallback. The dialog uses the native graph
  with a separate verified 227,350-byte untreated derivative; opening/editing/export
  installs the unchanged full original. No new marketing video or Three.js landing
  surface was added.
- Mark the first showcase image high priority. Use existing accessible action-purple
  tokens and locally increase muted-text contrast on both surfaces. Derive the
  disabled Community button name from its visible translated contents.

## Remaining cost

Mobile dashboard cold startup still scores 59: modeled LCP is 7.54 s, despite total
blocking time falling by about 81%. The report attributes approximately 1 s of modeled
script work to the client bootstrap/React chunk. Its main heading is the LCP element,
which appears after client-only Studio/runtime initialization. This pass does not
claim to solve that bootstrap architecture. A separate library entry that can show
its template shell before constructing editor services is the next substantial
change; it needs routing, storage/error and initial-focus regressions. Mobile landing
LCP remains approximately 4.4 s in the simulation. Preserving the actual cold workload
is more useful than delaying work past the audit or changing the throttling preset.

## Reproduction artifacts

Ignored `artifacts/lighthouse/` retains the actual `audit.mjs` harness, report HTML
and JSON, compressed traces/devtools logs, browser/GPU/settings records, exact source
file hashes, Git HEAD/diffs, matching production builds/maps and native browser logs.
The baseline, intermediate `candidate` and `final` builds are separate frozen trees;
`baseline-pointer` corrects only the desktop pointer environment. Preview servers
used ports 4187, 4188 and 4189. The user development server on port 6100 is unchanged.

The harness imports Lighthouse/Puppeteer from Bun's tool cache, launches the pinned
Chrome for Testing executable, and verifies the browser context ID before/after each
run. With those dependencies cached, the final audit command was:

```sh
systemd-run --user --scope --quiet -p CPUQuota=200% \
  -p MemoryHigh=2400M -p MemoryMax=3200M -p MemorySwapMax=0 \
  nice -n19 env NODE_OPTIONS=--max-old-space-size=1800 \
  node artifacts/lighthouse/audit.mjs final http://127.0.0.1:4189
```
