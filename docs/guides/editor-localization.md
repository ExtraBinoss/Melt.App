# Editor localization coverage

Interface resources belong to each feature’s `locales/*.json` files. `localeResources` discovers them at build time; importing the feature’s messages installs its i18next namespace. New copy should use these resources, including loading, error and accessible labels. Do not introduce component-level English/French `defaultValue` fallbacks.

The twelve advertised languages are English, French, German, Spanish, Italian, Portuguese, Dutch, Polish, Japanese, Korean, Chinese and Arabic. The SVG point editor, font picker, artboard headings, canvas Quick Add, studio loading, library cards, template catalogue and Motion preview namespaces have complete resource sets for these languages. Composition-mode controls and their conversion confirmation are translated in the Motion namespace. The common canvas hints, font label and composition name are also translated.

This does not establish translation completeness for the whole editor: older timeline, inspector and other namespaces continue to fall back to English where translations are absent. Brand names, font family names and editable artwork content are not automatically translated. CJK and Arabic font pickers use a neutral Latin brand/alphabet/numeric specimen, because many bundled fonts lack those scripts; localized sample sentences would silently preview the browser’s fallback font instead. Their controls remain localized. Arabic uses the application’s saved language and document `dir="rtl"`; vector geometry remains in its original coordinate system.

`apps/web/test/state/i18n/editor-resources.test.ts` checks complete feature coverage, nonempty values, interpolation variables, actual i18next resolution and consistent Static/Motion labels across the canvas and library. The focused artboard browser case checks French labels after persisted reload and Arabic controls with native inline SVG settings and font-popover focus round trips, including a decoded Inter specimen. Generated captures remain under ignored `artifacts/`.
